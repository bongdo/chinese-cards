# Решения

## 2026-10-22 — Свой текстовый формат `.deck`

Контекст: карточки приходят из рукописной тетради, дальше их будут править руками и агент.
Решение: один файл = колода, строки `вопрос = ответ [пиньинь] // заметка`, шапка `!deck`.
Почему: читается без инструментов, диффится построчно, парсится в 100 строк.
Что отвергли: Anki `.apkg` (бинарник, не правится руками), markdown-плагин Obsidian (тянет Obsidian).
Цена: свой парсер и свои правила, экосистемы нет.

## 2026-10-22 — Оценка только «знаю / не знаю»

Контекст: пользователь не хочет четырёх кнопок и настройки ease factor.
Решение: фиксированная лестница 0–1–3–7–16–40–90–200–400 дней, «не знаю» сбрасывает в ноль и возвращает через 10 минут.
Почему: предсказуемо, объяснимо, нечего настраивать.
Что отвергли: SM-2, FSRS (нужны оценки качества и калибровка).
Цена: нет адаптации под трудность карточки, только факт провала.

## 2026-10-22 — Go + SQLite на сервере, Expo на клиенте

Контекст: нужен свой сервис, который поднимет агент и который не сломается на VPS.
Решение: `net/http` + `modernc.org/sqlite` (без cgo), Expo SDK 58 + Expo Router.
Почему: один бинарник, ноль внешних сервисов, телефон собирается тем же TypeScript.
Что отвергли: Node-бэкенд, Postgres, нативная разработка под Android.
Цена: два языка и две проверки в `bin/check`.

## 2026-10-22 — Локальное зеркало и tombstones

Контекст: карточки нужны и на сервере, и на телефоне; правки и удаления должны доживать до сети.
Решение: `expo-sqlite` хранит копию карточек, флаг `dirty` для правок и таблицу `tombstones` для удалений; синхронизация через `GET /api/changes?since=`.
Почему: работает офлайн, удаление не «воскресает» при следующей загрузке.
Что отвергли: читать только с сервера (нет офлайна), полный CRDT (не нужен для одного пользователя).
Цена: конфликты решаются грубо — файл `.deck` главнее правки с телефона.

## 2026-10-22 — Адрес сервера зашит, настроек в приложении нет

Контекст: пользователь не хочет экрана настроек сервера и упоминаний Hermes.
Решение: базовый URL в `src/lib/config.ts`, переопределение только через `EXPO_PUBLIC_API_URL` при сборке.
Почему: одно приложение — один сервер, меньше экранов и ошибок.
Что отвергли: поле адреса и токена в UI, несколько профилей.
Цена: смена адреса требует пересборки.

## 2026-10-22 — EAS Build и EAS Update

Контекст: APK должен обновляться без проводов и без локального Android SDK.
Решение: сборка в облаке EAS, правки JS уезжают через `eas update` в канал `preview`.
Почему: не ставим JDK и SDK на VPS, обновление JS без переустановки.
Что отвергли: локальная сборка (3 ГБ и 2 ядра), Obtainium как единственный канал.
Цена: зависимость от аккаунта Expo и очередей сборки.

## 2026-10-22 — Публичный адрес через Tailscale Funnel, два URL в клиенте

Контекст: приложение должно работать и вне tailnet, но адрес в нём зашит.
Решение: основной адрес — tailnet IP, резервный — `https://server-riga.tailf358cb.ts.net` через Funnel; клиент перебирает их при сетевой ошибке.
Почему: внутри tailnet MagicDNS отдаёт имя как 100.x и TLS на узле не работает, снаружи Funnel отдаёт нормальный HTTPS.
Что отвергли: один публичный URL (ломается при включённом Tailscale), отдельный домен с сертификатом (лишний слой).
Цена: два адреса в конфиге и задержка на первую попытку, если сеть недоступна.

## 2026-10-22 — Токен для API, APK без токена

Контекст: Funnel выставил API в интернет.
Решение: `CARDS_TOKEN` в `~/.config/chinese/cards.env`, юнит читает его через `EnvironmentFile`; `/api/*` требуют Bearer, `/apk/*` и `/api/health` открыты.
Почему: сканеры не должны дёргать API, а Obtainium и браузер не умеют добавлять заголовки к скачиванию.
Что отвергли: закрыть всё токеном (ломает установку APK), basic-auth на прокси (лишний сервис).
Цена: токен лежит в бандле приложения — это защита от случайных сканеров, не от целенаправленного разбора APK.

## 2026-10-22 — Основной адрес — Funnel, tailnet IP — резерв

Контекст: пользователь хочет использовать `server-riga.tailf358cb.ts.net` как основной адрес; прямой публичный `:8787` провайдер закрывает.
Решение: `EXPO_PUBLIC_API_URL=https://server-riga.tailf358cb.ts.net`, резерв — `http://100.77.152.44:8787`; корень сайта и `/favicon.ico` открыты, API остаётся за токеном.
Почему: без Tailscale на телефоне работает Funnel; с включённым Tailscale первая попытка падает на 443 (там xray) и клиент сразу уходит на IP.
Что отвергли: домен с Let's Encrypt и Cloudflare Tunnel — пока нет домена; оставлять tailnet IP основным — не работает без Tailscale.
Цена: при включённом Tailscale один лишний неудачный запрос; адрес остаётся в зоне Tailscale.

## 2026-10-23 — API на Funnel-порту 10000, резервный http убран

Контекст: xray слушает `0.0.0.0:443`, поэтому tailscaled не может занять 443 на узле; клиенты, чей трафик приходит на узел локально (телефон через VPN, сам сервер), получали от xray HTTP/2 и `Unable to parse TLS packet header`.
Решение: `tailscale funnel --bg --https=10000 8787`, в клиенте один адрес `https://server-riga.tailf358cb.ts.net:10000`; резервный `http://100.77.152.44:8787` удалён, токен продублирован в EAS env `preview`.
Почему: 10000 разрешён Funnel, свободен на узле и работает в tailnet, снаружи и через VPN; cleartext-резерв в release-APK всё равно блокируется Android, а облачная сборка APK не видела `.env`.
Что отвергли: перенос xray с 443 (сломает клиентов VPN), `usesCleartextTraffic` (пересборка и ослабление ради мёртвого пути).
Цена: нестандартный порт в адресе; адрес снова придётся менять, если 10000 займут.

## 2026-10-23 — Расписание и статистика считаются на телефоне

Контекст: очередь и статистика запрашивались у сервера, поэтому до ответа сети экран был пустым, а «Учить всё» не работало без связи.
Решение: лестница интервалов повторена в `mobile/src/lib/scheduler.ts`; ответ сразу пишется в локальные `cards` и `reviews`, статистика и очередь строятся из SQLite, сервер получает только `POST /api/review` для своей истории. TTS — `expo-speech` с системным голосом `zh-CN`.
Почему: экран открывается из кеша и работает в авиарежиме; совпадение лестницы с Go закреплено тестом `scheduler.test.ts` в `bin/check`.
Что отвергли: тянуть историю отзывов с сервера (новый endpoint и дедупликация), нейросетевую TTS-модель (десятки МБ и нативный рантайм ради произношения).
Цена: локальная история статистики начинается с этого обновления; голос звучит только если в системе установлен китайский движок TTS.

## 2026-10-23 — Расписание считает только телефон, сервер хранит результат

Контекст: `POST /api/review` считал лестницу сам, клиент считал её локально и выбрасывал ответ сервера; после pull побеждал записавший последним.
Решение: клиент присылает в `/api/review` готовые `box`, `due_at`, `lapses`, `reps`, сервер сохраняет их как есть; без этих полей (агент, старый клиент) сервер считает сам.
Почему: источник правды один — локальная база, как решено 2026-10-23; офлайн и сервер сходятся без второго расписания.
Что отвергли: применять ответ сервера на телефоне (снова зависимость от сети), убрать расчёт на сервере совсем (агентские вызовы без полей).
Цена: сервер доверяет расписанию клиента, проверяются только диапазоны.

## 2026-10-23 — Дедуп ответов по id события

Контекст: при таймауте fetch ответ уходил в outbox, flush повторял его, и сервер записывал второй ответ, если первый дошёл.
Решение: клиент генерирует `event_id` на каждый ответ и шлёт его и сразу, и из outbox; сервер пишет id в `review_events` и повтор с тем же id не применяет.
Почему: на мобильной сети потеря ответа — обычный случай; id дешевле, чем сверка времени и состояния.
Что отвергли: дедуп по `(card_id, ts)` (таймстемпы расходятся), проверку «последний ответ» (гонки).
Цена: старые записи outbox без id не дедуплицируются; таблица растёт вместе с историей.

## 2026-10-23 — Один адрес без ротации

Контекст: в `api.ts` остался массив из одного адреса с `preferred`-ротацией; резервный URL убран ещё 2026-10-23, код врал про failover.
Решение: `API_URL` из `config.ts` используется напрямую; `Config.baseUrl`, `api.health`, `outbox.pendingCount` удалены.
Почему: мёртвая абстракция дороже одной строки и обещает то, чего приложение не умеет.
Что отвергли: оставить массив на будущее (нет второго адреса и плана).
Цена: смена адреса по-прежнему требует пересборки. Заменяет 2026-10-22 «Публичный адрес через Tailscale Funnel, два URL в клиенте» в части резерва.
